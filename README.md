# Film Engine

Narrated product demo films, built from code: a voice track with word timings, a browser capture whose clicks and zooms fire on the narrator's words, a camera pass that follows a few rules, a Remotion edit with motion blur, word-by-word captions, interface sounds, ducked music and animated number cards, and a finishing pass. One small example film is included and runs without any client app.

## Requirements

- Node 20 or newer (npm 10 or newer)
- Python 3.11 or newer, with Playwright and its Chromium
- ffmpeg and ffprobe on the PATH (`brew install ffmpeg` on a Mac)
- An ElevenLabs API key for the voice and the speech-to-text check. Without one, use the open-source voice (Kokoro, below) or the silent `--no-voice` mode.

```bash
cd film-engine
```

## Try the example first

The example is a made-up invoice checker called Tally, a single static page in `examples/hello-demo/site/`. The kit serves the page itself during the shoot, so nothing else needs to run. The film has four scenes and lasts about 20 seconds: an animated number card, two footage scenes (typing, clicks, zooms) and an end card.

```bash
bash kit/run.sh examples/hello-demo --no-voice         # silent placeholder voice: no key, no cost
TTS_BACKEND=kokoro bash kit/run.sh examples/hello-demo # open-source voice, runs locally
bash kit/run.sh examples/hello-demo                    # ElevenLabs voice (needs ELEVENLABS_API_KEY)
```

`run.sh` makes the interface sounds and the music pad on its first run, and keeps existing takes and clips. To switch voices, delete `public/hello-demo/` first (or pass `--force` to `kit/tts.py`). Each run writes `out/hello-demo/hello-demo-vN.mp4`, a `-web` copy and a contact sheet, with the next free version number.

## The workflow

One film is one folder: `film.json` (settings), `script.json` (scenes and narration), `cards.json` (optional title cards) and `shoot.py` (what happens on screen). Copy `examples/hello-demo` to start a new film.

**1. Write the script.** Each scene in `script.json` is either footage or a card. Write the narration first, one sentence per scene, then check the script:

```bash
python kit/qa/lint_script.py films/my-film
```

**2. Generate the voice.** One take per scene, with a start and end time for every word:

```bash
python kit/tts.py films/my-film                    # all scenes that have no take yet
python kit/tts.py films/my-film s03 s04            # redo these takes
python kit/qa/stt_check.py films/my-film           # every take must match the script word for word
```

Listen to each take. If a word comes out wrong (a number, a name, an abbreviation), respell it in the script and redo that take.

**3. Shoot.** Start the app you are filming (or set `"serve"` for a static site), then:

```bash
python kit/shoot.py films/my-film                  # all footage scenes
python kit/shoot.py films/my-film s05              # one scene
python kit/shoot.py films/my-film --draft          # quick 1x capture while you work out the cues
```

Each scene prints its frame rate. Anything under 20 fps fails; see the capture rules below.

**4. Build the camera and the film data.**

```bash
python kit/build_data.py films/my-film
```

This step applies the camera rules and prints a `camera:` line for every jitter or double zoom. Fix those in `shoot.py` (usually by deleting a zoom cue) and shoot that scene again. Aim for "camera: no warnings".

**5. Render.**

```bash
npx remotion studio src/index.ts                   # preview and scrub in the browser
npx remotion render src/index.ts Film out/my-film/render-v1.mp4 --codec=h264 --crf=16
```

**6. Finish.**

```bash
bash kit/finish.sh out/my-film/render-v1.mp4 out/my-film/my-film-v1.mp4
```

The master keeps the 1920x1200 picture with loudness at -16 LUFS; `my-film-v1-web.mp4` is 1440x900 at crf 25 for email and the web. The script refuses to overwrite a finished file: bump the version instead.

**7. QA.**

```bash
python kit/qa/stt_check.py films/my-film --master out/my-film/my-film-v1.mp4
bash kit/qa/sheet.sh out/my-film/my-film-v1.mp4 out/my-film/sheet-v1.png 1 5
bash kit/qa/sheet.sh public/my-film/clips/s05.mp4 out/my-film/s05-sheet.png 0.5 6   # one raw clip
```

Open the contact sheets and look at every frame: nothing private on screen, zooms land on what the voice is talking about, captions and source lines readable, no blank or frozen stretches.

`bash kit/run.sh films/my-film` runs steps 1 to 7 in order.

## Effects

All of these are on by default and come from data the pipeline already has, so they stay in sync without hand editing.

- **Motion blur on camera moves.** While the camera zooms or pans, each frame blends eight sub-frame camera positions, like a film camera's shutter. Frames where the camera is still are drawn once, so render time only grows during moves. Tune `SHUTTER` and `BLUR_SAMPLES` at the top of `src/Film.tsx` (`SHUTTER = 0` turns the blur off).
- **Word-by-word captions.** Each word in the caption lights up as the narrator says it, using the take's word timings. Set `"captions": "plain"` or `"none"` in `film.json` to change that.
- **Interface sounds.** A soft click on every mouse press and a light tick on every key press, placed on the exact moments the capture logged. `kit/make_sfx.sh` makes the sounds from filtered noise, so there are no sample files or licences to track. Replace the files in `public/sfx/` with your own (CC0 packs such as Kenney's UI Audio work), or set `"sfx": false`.
- **Music that ducks under the voice.** The music dips while the narrator speaks and comes back up in the pauses; the dips come from the word timings, so they land exactly. Put a licensed track in `public/` and set `"music"` in `film.json`; the synth pad from `kit/make_pad.sh` is only a placeholder. Levels: `MUSIC_LEVEL`, `DUCK` and `DUCK_RAMP` in `src/Film.tsx`.

## The script file

```json
[
 {
  "id": "p1", "card": "number", "tail": 0.8,
  "marks": {"count": "four hours"},
  "props": {"kicker": "Example", "title": "Time spent checking invoices by hand",
            "stats": [{"value": 4, "suffix": " h", "label": "a week, per team", "mark": "count"}],
            "source": "Invented figure for this demo film."},
  "text": "Small teams spend about four hours a week checking invoices by hand."
 },
 {
  "id": "s02", "label": "Check an invoice", "tail": 1.5,
  "tags": [{"at": "vendor's name", "dur": 3.0, "text": "Demo data: invented vendor and invoice"}],
  "text": "Type the vendor's name and press Check."
 }
]
```

| Field | Meaning |
|---|---|
| `id` | Scene id. Footage scenes need a function with the same name in `shoot.py`. |
| `text` | The narration. ElevenLabs `<break time="0.4s" />` tags are allowed. |
| `label` | Pill shown at the top left when the label changes. Leave empty on cards. |
| `tail` | Seconds held after the narration ends (default 0.55 for footage, 0.9 for cards). |
| `tags` | Lower-third lines over footage: `at` is a phrase from the text, `dur` is seconds. Use them for sources and "demo data" notes. |
| `card` | `number`, `bars`, `timeline`, `pipeline` or `cta`. Without it, the scene is footage. |
| `props` | The card's content. See the comment at the top of `src/Cards.tsx` and `src/Pipeline.tsx`. |
| `marks` | Card animation triggers: name → a phrase from the text. The counter starts when the phrase is spoken. |

`cards.json` holds optional `intro` and `outro` title cards (`kicker`, `title`, `sub`, `dur`); a `dur` of 0 turns them off. The example has none: the hook card opens the film and the cta card ends the film.

## How to write cues

A cue ties an action to a phrase in the scene's narration:

```python
def s03(sc):
    sc.prepare(go("/invoices/1042", "#lines"))        # off camera: open the page, wait for it
    sc.start()                                        # recording starts; the voice starts 0.45 s later
    sc.cue("three lines", lambda s: s.zoom("#lines"), early=0.3)
    sc.cue("purchase order", lambda s: s.click("#row-toner"), early=0.7)
    sc.finish()                                       # holds for the tail, then encodes the clip
```

- **Phrases are exact words from the scene's text**, two or three words long, so they are unique. Punctuation and case are ignored. A missing phrase stops the shoot with an error that names the phrase.
- **`early` is how many seconds before the phrase the action starts.** The cursor travels for about half a second before a click, so clicks need `early=0.5` to `0.9` to land as the word is spoken. Zooms need about `0.3`.
- **Actions run one after another.** If one runs long (typing a long string), the next cue starts late and the shoot prints `(late: ...)`. Type shorter strings, lower the typing delay, or move the cue later.
- **Zooms:** `s.zoom("#selector")` frames that element from now on; `s.zoom(None)` returns to the full page. `union(sel, n)` from `cap.py` frames a group (the first n rows of a list). Use one zoom per idea, not one per sentence.
- **Set the page up off camera** inside `prepare()`: log in, fill forms, scroll. The viewer should only see what the narration is about.
- Helpers in `cap.py`: `go(path, wait)`, `top_at(sel, y)` (instant scroll, off camera), `glide_to(sel, y)` (eased scroll, on camera), `union(sel, n)`, plus `s.click`, `s.type`, `s.move`, `s.mark`.
- `CUELOG=1 python kit/shoot.py ...` prints when each cue wanted to fire and when it did.

## The rules we learned

**Camera**
- Pull back before every click outside the zoomed element, so the viewer sees what gets clicked. `build_data.py` adds that pull-back one second before the click.
- No zoom held longer than about 3.5 s. Longer zooms end on their own at 3.4 s.
- Zoom tops out at 1.9x. Past that, text in the capture goes soft.
- No double zooms (in, out and back in within 1.5 s) and no jitter (a zoom shorter than 1.2 s, or a pull-back shorter than 1.8 s). `build_data.py` warns about both; fix them by deleting zoom cues, not by adding more.

**Capture**
- The frame rate must be at least 20 fps. Pause screen recorders, GeForce NOW and other GPU-heavy apps during a shoot; they starve the capture.
- Capture at device scale 2 for the final film. `--draft` is for working out cues.
- Use the port your app already runs on, or a free one. Never stop a process you did not start to free a port.

**Narration**
- One sentence per scene. A second sentence usually means a second scene.
- Never "it" for the product. Say the product's name, or rephrase so a person is the subject ("you get", "the team sees").
- No internal version names (engine v3, beta, the new model) in the voice or on screen.
- Every number on screen carries a plain-English source line: "Source: 1,200 support tickets from our helpdesk, January to June 2026", not a file path. Label estimates as estimates.
- Never show prospects your own unit cost (compute, API fees, cost per run). Show their cost and their savings.
- Frame backtests honestly: say how many projects, that the answers were hidden and compared afterwards, and how matches were counted ("one project, matched by hand"). Never invent a saving, a customer or a testimonial.
- Spell numbers the way they should be spoken ("thirty-eight", "sixty thousand dollars"); voices misread digits.
- No hype words, no slogan title cards. Plain, specific and confident.

**Privacy**
- Never film a client's drawings, documents or data without written permission. Film public records or invented demo data, and say so in a tag ("Demo data: public records").
- Results from a private project may appear only as anonymous numbers.
- Put client names, addresses and owner names in `banned` in `film.json`, and keep private files out of the film folder.

**QA**
- Speech-to-text of every take and of the finished master must match the script word for word.
- Look at the contact sheets of the raw clips and of the final film before anyone else sees the film.
- Never overwrite a finished file; make a new version.

## Open-source audio

Set `TTS_BACKEND=kokoro` (or `"tts_backend": "kokoro"` in `film.json`) to make the voice with [Kokoro-82M](https://huggingface.co/hexgrad/Kokoro-82M) instead of ElevenLabs. Kokoro runs locally on the CPU (and on Apple Silicon), with no account and no per-use cost. Kokoro returns audio without word timings, so `kit/align.py` runs faster-whisper over each take with word timestamps and maps the heard words back onto the script's own words. The take's `.json` then has the same format as an ElevenLabs take, and the shoot cues work unchanged. Without an ElevenLabs key, `kit/qa/stt_check.py` uses faster-whisper as well.

**Install**

```bash
pip install -r requirements-kokoro.txt      # kokoro, soundfile, faster-whisper (PyTorch comes with kokoro: about 1.3 GB in total)
TTS_BACKEND=kokoro python kit/tts.py examples/hello-demo --force
```

The first run downloads the Kokoro model, a small spaCy English model and the Whisper `small.en` model. Kokoro's fallback phonemiser (espeak-ng, bundled with the pip package) cannot load its data from a long path; when the virtualenv sits deep in the file system, the kit copies that data to `~/.cache/film-engine/` once. No separate espeak-ng install is needed.

**Picking a voice.** Set `kokoro_voice` in `film.json` or `KOKORO_VOICE`. The prefix sets accent and gender: `af_` American female, `am_` American male, `bf_` British female, `bm_` British male. The model card's [voice list](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md) grades each voice; the strongest American English voices are `af_heart` (A) and `af_bella` (A-), and the strongest British one is `bf_emma` (B-). Most male voices are graded C+ or lower. `kokoro_speed` (default 0.92) slows or speeds the read. Make one take with each candidate voice and listen before you decide.

**Honest notes**
- Quality is a step below ElevenLabs v4: flatter emphasis, less natural pauses, and the occasional odd stress on a long sentence. Fine for drafts, internal reviews and many demos; for a film that goes to buyers, compare against an ElevenLabs take first.
- Check how numbers, names and abbreviations are spoken. Spell them the way they should sound, and run the STT check.
- Local speech-to-text can mishear invented product names ("Tally" heard as "Tali"). List those names in `names` in `film.json`; the kit passes them to Whisper as a hint. If the check still flags a name, listen to that take yourself.
- Alignment prints a warning when fewer than 85% of the script's words were heard as written. That usually means a mispronounced or skipped word: listen to the take.

## Licences of the tools in the kit

- **Remotion** (the video edit) is not fully free for companies. Its [licence](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md) is free for individuals, non-profits and for-profit organisations with up to 3 employees; larger for-profit companies need a paid Company License. Read the licence before using the kit commercially in a larger team.
- **[HyperFrames](https://github.com/heygen-com/hyperframes)** (by HeyGen, Apache-2.0, no per-render fees or commercial thresholds) renders HTML and CSS animations to MP4 with headless Chrome and FFmpeg. The same job as the `src/` folder here, so HyperFrames is the way out if the Remotion licence does not fit. Moving over means rewriting `Film.tsx`, `Cards.tsx` and `Pipeline.tsx` as HTML compositions; `kit/` (voice, capture, camera rules, QA) stays as is, because `build_data.py` would write the same timing data for either renderer.
- Playwright, React and ffmpeg's command-line tools are open source (Apache-2.0, MIT, and LGPL/GPL respectively). Kokoro and the other voice models are covered in "Open-source audio".

## Before you share a film folder or the kit

```bash
bash kit/qa/check_secrets.sh <folder> ~/private-terms.txt
```

The check fails on key-shaped strings, `.env` files, audio and video files, dependency and cache folders, absolute paths to someone's machine, and any word in the terms file (one per line: client names, addresses, owner names). Keep the terms file outside the folder you check.

## Troubleshooting

- **`cue not found in the take`**: the phrase in `shoot.py` is not in the scene's text, or the text changed after the take was made. Copy the words from the script.
- **A click lands late or early**: change `early` for that cue; `CUELOG=1` shows the timing.
- **`port 4173 is busy`**: `PORT=4180 python kit/shoot.py ...`.
- **Under 20 fps**: close screen recorders, GeForce NOW, video calls and heavy browser tabs, then shoot again.
- **Remotion cannot find a clip or take**: run `kit/build_data.py` again after any new take or shoot; `src/data.ts` points at the current files.
- **A Kokoro take ends abruptly or skips a word**: shorten the sentence, respell the word, or try another voice.

## For Claude

These notes are for Claude Code (or another coding agent) working in this kit on someone's behalf. Claude Code also finds them as the `demo-film` skill in `.claude/skills/demo-film/SKILL.md` when started in this folder.

1. **Read first:** this README, `examples/hello-demo/` (all files), `kit/cap.py` (the Scene API and helpers) and the comment at the top of `src/Cards.tsx`.
2. **Check the setup** before anything else: `node -v` (20+), `python --version` (3.11+), `ffmpeg -version`, `python -c "import playwright"`, and whether `ELEVENLABS_API_KEY` is set (`[ -n "$ELEVENLABS_API_KEY" ] && echo set`). Never print, log or write the key. If the key is missing, say so and offer `TTS_BACKEND=kokoro` or `--no-voice`.
3. **Prove the pipeline works** on this machine with `bash kit/run.sh examples/hello-demo --no-voice` before starting a real film.
4. **New film:** copy `examples/hello-demo` to `films/<name>/`. Ask for the audience, the one action the film should lead to, the URL and port of the app, how to log in, which records are public or invented, and the source of every number. Do not guess numbers or sources.
5. **Script:** one sentence per scene; a hook card first, footage in the middle, proof cards, a cta card last; 75 to 110 seconds for a sales film. Run `python kit/qa/lint_script.py films/<name>` until there are no errors, and show the script to the person before generating voice.
6. **Voice:** `python kit/tts.py films/<name>`, then `python kit/qa/stt_check.py films/<name>`. Fix mismatches by respelling and regenerating only those takes (`python kit/tts.py films/<name> <id>`).
7. **Shoot:** find stable selectors in the app first (a short Playwright script that prints ids, roles and headings). Write one function per footage scene. Shoot with `--draft` while working out cues, then at full quality. Never stop processes you did not start; ask which port to use.
8. **Camera:** run `python kit/build_data.py films/<name>` after every shoot. Fix every `camera:` warning by deleting or moving zoom cues, then shoot that scene again. Never ship with camera warnings.
9. **Render, finish, QA:** render to `out/<name>/render-vN.mp4`, finish to `out/<name>/<name>-vN.mp4`, make contact sheets of the master and of each raw clip, then look at the sheets yourself (read the PNGs) and run the STT check on the master. Report anything private or wrong you see.
10. **Hard rules:** follow "The rules we learned" above. Never film client data without written permission. Never show the product's own unit cost. Every on-screen number has a plain-English source. Never overwrite a finished file. Run `kit/qa/check_secrets.sh` before anything leaves the machine, and never upload or send files unless asked.
11. **Report back** with the master path, its length, the loudness line from `finish.sh`, the STT result, the camera check result, and any rule you could not meet.
